## Request

User reported Tiger bạc price `17.500đ` now shows fractional `17,5K` only on printed/customer bill, while other interfaces still round to `18K`. Fix all repository UI price displays to preserve fractional-thousand values.

## Root cause

`app/utils/format.js#compactNumber()` and the `store.js#fmt` fallback used `(value / 1000).toFixed(0) + 'K'`, so every UI surface that calls `fmt(m.price)` rounded `17.500đ` to `18K`.

Known affected UI surfaces found by scan include:

- POS menu grid: `renderMenuItems()` → `fmt(m.price)`
- Cart/order row totals: `renderCart()` → `fmt(item.price * item.qty)`
- Bill item line totals: `openBillModal()` → `fmt(i.price * i.qty)`
- Menu admin list: `renderMenuAdmin()` → `fmt(m.price)`
- Purchase/order detail views that use the same compact formatter

## Changes

- Updated `app/utils/format.js#compactNumber()` to preserve fractional thousands with Vietnamese locale formatting.
- Updated `store.js` fallback `fmt` to use the same exact fractional-K behavior if the extracted formatter is unavailable.
- Bumped `index.html` cache key for `app/utils/format.js` to `20260604-exact-price-ui` so deployed/mobile clients fetch the fixed formatter.
- Extended `scripts/verify-format-utils.js` with exact display assertions:
  - `17500` → `17,5K`
  - `17550` → `17,55K`
  - `18000` → `18K`
- Added verifier guards to prevent reintroducing `toFixed(0)` rounding in the compact thousand formatter.
